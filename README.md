# zynqboard_petalinux

PetaLinux 2020.2 project for the HZHY HZ7020 (Zynq-7000) board, with LCD support via Xilinx DRM/KMS.

> **Prerequisite:** Before building, copy the vendor-modified Linux 5.4 kernel source tree into `hz7020_fresh/components/ext_sources/zynq-linux-xlnx/`; the `components/ext_sources/` directory is intentionally excluded by `.gitignore` and is therefore not included in this repository.

## Boot flow

```
BOOT.BIN (FSBL + bitstream + U-Boot)  ->  U-Boot distro boot  ->  boot.scr (FAT p1)
     ->  fatload image.ub  ->  kernel + device tree (FIT)  ->  rootfs on /dev/mmcblk0p2
```

SD card layout:

| Partition | Filesystem | Contents |
|---|---|---|
| p1 | FAT32 (bootable) | `BOOT.BIN`, `image.ub`, `boot.scr` |
| p2 | ext4 | extracted `rootfs.tar.gz` |

The vendor "Open Source" flow (`zImage` + `system.dtb` + `ramdisk.gz.uboot` + vendor `boot.scr`) is **not** used here. Do not mix the two sets of files on the same card: the U-Boot environment generated by PetaLinux expects `image.ub`, and the stock script contains fallback branches that may pick up leftover files.

## The `boot.scr` problem and how to fix it

The `boot.scr` produced by PetaLinux decides whether to boot `image.ub` with a path test:

```sh
if test -e ${devtype} ${devnum}:${distro_bootpart} /image.ub; then
    fatload ${devtype} ${devnum}:${distro_bootpart} 0x10000000 image.ub;
    bootm 0x10000000; exit;
fi
```

On this board that test can evaluate to **false even when `image.ub` is present on the FAT partition**. The script then skips every fallback branch and finally executes the last line of the script, `bootm 0x00200000 - 0x00100000`, which points at empty memory, so U-Boot reports:

```
## Executing script at 03000000
Wrong Image Format for bootm command
ERROR: can't get kernel image!
SCRIPT FAILED: continuing...
```

A manual `fatload mmc 0:1 0x10000000 image.ub` followed by `bootm 0x10000000` boots fine, which proves the image and the card layout are correct — only the existence test is unreliable.

The fix is to use the **exit status of `fatload` itself** as the test, and regenerate `boot.scr` with `mkimage`. The script below does that.

### `make-boot-scr.sh`

```bash
#!/usr/bin/env bash
# make-boot-scr.sh - regenerate images/linux/boot.scr for the HZHY HZ7020 board.
#
# Why: the stock PetaLinux boot.scr decides whether to boot image.ub with
#   if test -e ${devtype} ${devnum}:${distro_bootpart} /image.ub
# which can evaluate to false on this board even when the file is present.
# The script then falls through to "bootm 0x00200000 - 0x00100000" and U-Boot
# reports "Wrong Image Format for bootm command".
# Using the exit status of fatload itself is reliable.
#
# Usage: ./make-boot-scr.sh [project_dir]
#        (default project_dir: $HOME/petalinux/projects/hz7020_fresh)

set -euo pipefail

PROJ_DIR="${1:-$HOME/petalinux/projects/hz7020_fresh}"
BOOT_SCR="$PROJ_DIR/images/linux/boot.scr"
FIT_LOAD_ADDR="0x10000000"

command -v mkimage >/dev/null 2>&1 || {
	echo "mkimage not found. Install it with: sudo apt install -y u-boot-tools" >&2
	exit 1
}

if [ ! -d "$PROJ_DIR/images/linux" ]; then
	echo "not a PetaLinux project directory: $PROJ_DIR" >&2
	exit 1
fi

WORK_DIR="$(mktemp -d)"
trap 'rm -rf "$WORK_DIR"' EXIT

# ${boot_targets}, ${devtype}, ${devnum}, ${distro_bootpart} stay literal:
# they are expanded by U-Boot at run time, not by the shell.
cat > "$WORK_DIR/boot.cmd" <<EOF
for boot_target in \${boot_targets};
do
	if test "\${boot_target}" = "mmc0" || test "\${boot_target}" = "mmc1"; then
		if fatload \${devtype} \${devnum}:\${distro_bootpart} ${FIT_LOAD_ADDR} image.ub; then
			bootm ${FIT_LOAD_ADDR};
			exit;
		fi;
	fi;
done;
echo "boot.scr: image.ub not found or not loadable, dropping to U-Boot prompt";
EOF

mkimage -A arm -T script -C none -n "PetaLinux boot script (image.ub)" \
	-d "$WORK_DIR/boot.cmd" "$BOOT_SCR"

echo "generated: $BOOT_SCR"
ls -l "$BOOT_SCR"
```

### Usage

```bash
# on the host (WSL)
sudo apt install -y u-boot-tools        # provides mkimage, once
chmod +x make-boot-scr.sh
./make-boot-scr.sh

# copy to the FAT partition of the SD card, next to BOOT.BIN and image.ub
cp hz7020_fresh/images/linux/boot.scr /media/sd-boot/
sync
```

No PetaLinux rebuild is required: `boot.scr` is only a file on the FAT partition. If your U-Boot environment exports `kernel_addr_r`, you may replace `0x10000000` with `${kernel_addr_r}`.

### Verify before booting

`boot.scr` is a 64-byte `mkimage` header followed by the plain-text script:

```bash
dd if=hz7020_fresh/images/linux/boot.scr bs=64 skip=1 2>/dev/null | tr -d '\000'
```

The output should show the `fatload ... image.ub` branch. A healthy file is about 200-300 bytes.

### Alternative: `uEnv.txt`

If you do not want to touch `boot.scr`, drop a plain-text `uEnv.txt` on the FAT partition:

```
bootcmd=fatload mmc 0:1 0x10000000 image.ub && bootm 0x10000000
```

U-Boot imports it before running the script and overrides `bootcmd`. Keep in mind that any leftover `uEnv.txt` also overrides later experiments, and that `boot.scr` is still executed by distro boot.

### Making it permanent inside the project

The manual script above only fixes the copy on the SD card; the next `petalinux-build` regenerates `images/linux/boot.scr`. To change it in-tree, edit the template used by the `u-boot-zynq-scr` recipe and rebuild just that recipe:

```bash
# the bbappend sets FILESEXTRAPATHS to ${THISDIR}/${PN} and BOOTFILE_EXT = ".initrd",
# so the template actually compiled is boot.cmd.default.initrd
vi hz7020_fresh/project-spec/meta-user/recipes-bsp/u-boot/u-boot-zynq-scr/boot.cmd.default.initrd

petalinux-build -c u-boot-zynq-scr
```

Then re-copy `hz7020_fresh/images/linux/boot.scr` to the card. This is the recommended long-term fix, because it survives `petalinux-build` and `petalinux-package --boot`.
